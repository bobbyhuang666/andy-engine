## 4. 诊断方法

`scripts/l4-divergence-diag.js`：

1. 跑 full run（seed42/100ticks），逐 tick 采状态快照 `fullState[tick]`。
2. 跑 restored run（tick 50 序列化→恢复→续跑到 100），逐 tick 采 `restoredState[tick]`。
3. 逐 tick 比对，定位**首个分叉 tick**（首个 `fullState[t] !== restoredState[t]` 的 t）。
4. 在首个分叉 tick，dump 字段级 diff，定位**首个分叉字段**。
5. 在分叉 tick，dump：RNG state、pendingEvents、_scheduledEvents、_nextId、agent 标量、memory count。

每 tick 采的状态（dump 字段）：

```text
worldClock.time / tickCount
rngState
EventDispatcher.pendingEvents (长度 + 内容)
EventDispatcher._nextId
EventDispatcher.eventIndex
AndyWorld._scheduledEvents (长度 + 内容)
每 agent: position / stateMachine.current / memory.memories.length / emotion (前3维) / behaviorField.B / needs (前3)
socialGraph edges
events.eventLog length
```

## 5. W0 必须回答的 7 个问题

报告 `docs/current/PERSISTENCE_FIDELITY_ROOT_CAUSE_REPORT.md` 必须明确回答：

1. **首个分叉 tick 是多少？**（精确 tick 号）
2. **首个分叉字段是什么？**（字段级，非"agent 状态"笼统）
3. **分叉前 RNG state 是否一致？**（恢复点 tick 50 + 分叉 tick-1）
4. **分叉是否由 EventDispatcher 导致？**（pendingEvents/_nextId/eventIndex 哪个先分叉，还是其他字段先分叉）
5. **是否存在其他未持久化 runtime state 参与分叉？**（AndyWorld._scheduledEvents 是否参与，审计 §1.4 的 4 项逐一验证）
6. **修复是否仍需要 schemaVersion bump？**（视根因是否触及 runtimeSnapshot 结构）
7. **哪些测试应改写，哪些旧诊断应删除？**（W6 错误诊断测试处理 + 真正根因 regression test 建议）
