# v2.3-W3 任务卡 — Replay Observability Diagnostic Hashes

> 阶段：v2.3-W3 实现（诊断工具改进，不改模拟语义）
> 触及边界：**否**（新增诊断 hash + replay-diff 分层输出，不进 release gate，不改 tickHash 语义，不改 src/ 模拟逻辑）
> 状态：总规划师授权启动（W2 safety net 已就位，W3 风险低）
> 依赖：v2.3-W2（characterization tests 已建成）

## 1. 背景

v2.2 诊断链 5 层逐层挖根因（W0→W0c→W0e→W0f），若有分层 hash 能从四轮缩到一轮——首分叉层直接指示根因层。W3 新增诊断 hash + replay-diff 分层输出，提升未来诊断效率。

## 2. 边界（全程有效）

- 不进 release gate（诊断工具，不阻塞发版）。
- 不改变 tickHash 语义（HASHED_FIELDS 不变）。
- 不改 src/ 模拟逻辑（仅新增 hash 计算 + replay-diff 输出）。
- 不改 Stable Envelope / schemaVersion / public API。
- 不引入 LLM narrative replay。

## 3. 写入边界

| 文件 | 改动 | 说明 |
|---|---|---|
| `src/store/world/tickHash.js` | 增函数 | `computeEventLogHash` / `computeMemoryHash` / `computeAgentStateHash`（诊断用，复用 canonicalize） |

| `tests/unit/diagnostic-hashes.test.js` | 新建 | 测试诊断 hash 计算 + 分层输出格式 |

**不得改**：tickHash 的 HASHED_FIELDS / computeTickHash 语义、Stable Envelope、public API、release gate、src/ 模拟逻辑、既有测试。

## 4. 诊断 hash 设计

复用 tickHash 的 canonicalize（递归 key sort + 1e9 量化 + sha256）：

| hash | 覆盖字段 | 用途 |
|---|---|---|
| `tickHash`（现有） | worldClock / characters / relationships / canonFacts / positions | L4 release gate |
| `eventLogHash`（新） | eventLog id 序列 + type + content | event 演化诊断 |
| `memoryHash`（新） | 每 agent memory ids + importance + accessCount 摘要 | memory 演化诊断 |
| `agentStateHash`（新） | emotion / behaviorField / needs 摘要 | agent 内部状态诊断 |

诊断 hash **不进 golden fixture**（fixture 仅含 tickHashes）。诊断 hash 在 replay-diff 运行时实时计算比对。

## 5. replay-diff 分层输出

```text
Layer 1 (tickHash):       tick 67 mismatch  ← 当前
Layer 2 (eventLogHash):   tick 60 mismatch  ← 指向 event 层
Layer 3 (memoryHash):     tick 60 mismatch  ← 指向 memory 层
Layer 4 (agentStateHash): tick 67 mismatch  ← 指向 emotion 层
```

首分叉层直接指示根因层。诊断 hash 不阻塞（exit code 仍由 tickHash 决定）。
