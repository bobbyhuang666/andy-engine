# v2.3-W1 任务卡 — Memory simTime Consistency

> 阶段：v2.3-W1 实现（小修，优先启动）
> 触及边界：**否**（PersonalMemory 内部初值改 deterministic，不触及 Stable Envelope / public API / release gate）
> 状态：总规划师已批准优先启动
> 依赖：无（v2.2-W1 已完成，L4 达标）

## 1. 背景

v2.3 Design Brief §1 确认：`PersonalMemory._simTime` 初值 `Date.now()`（`PersonalMemory.js:49`），与 `ProceduralMemory._simTime = 0`（`ProceduralMemory.js:36`）不一致。

构造到 setSimTime 间的墙上时钟渗漏：
- line 97 `createdAt: this._simTime`（seed memory 创建）
- line 172-174 `timestamp/lastAccessed/presentations: new Date(this._simTime)`（addExperience 新 memory）

setSimTime（`AgentRuntime.tick` line 84）每 tick 覆盖，但首 tick 前的 seed memory / 构造期 addExperience 用墙上时钟。

## 2. 写入边界

| 文件 | 改动 | 说明 |
|---|---|---|
| `src/agent/memory/PersonalMemory.js` | line 49 `_simTime = Date.now()` → `_simTime = 0` | 与 ProceduralMemory 一致，消除墙上时钟渗漏 |
| `tests/unit/memory-simtime-consistency.test.js` | 新建 | characterization test：setSimTime 前 _simTime=0，setSimTime 后用 sim time |

**不得改**：ProceduralMemory（已是 0）、Stable Envelope、public API、release gate、tickHash 算法、其他 src/。

## 3. characterization test 设计

- 构造 PersonalMemory，断言 `_simTime === 0`（setSimTime 前 deterministic）。
- 调 `setSimTime(new Date('2026-09-01T08:00:00Z'))`，断言 `_simTime === simTime.getTime()`。
- 构造后未 setSimTime 时 addExperience 产生的 memory timestamp 用 _simTime=0（deterministic，非墙上时钟）。
- 对比 ProceduralMemory 行为一致（两者初值都是 0）。

## 4. 验收命令

```bash
npm test                    # 含新 characterization test
npm run test:domain
npm run check:boundaries
npm run smoke:pack
npm run perf:check
npm run replay:diff         # 验证是否 golden drift
```

关键验收点：
- characterization test pass。
- L4 主测试仍 pass（_simTime 不进 tickHash，但 seed memory timestamp 变可能影响 golden fixture）。
- replay:diff：若 hash drift，经人审确认为 intentional（seed memory timestamp 改变）→ golden:regen + changelog。

## 5. 风险与回退

- **风险**：seed memory timestamp 从墙上时钟改为 0，可能改变 golden fixture 的 memory timestamp 字段 → golden-seed-replay 全等 fail。
- **缓解**：seed memory 在 createCharacter 时已由 `backgroundToMemories(background, simTime)` 传 simTime（v2.2 修复），line 49 初值主要影响构造期。需实测确认 golden drift 范围。
- **回退**：若 golden drift 过大或 L4 fail，回滚 line 49 改动。

## 6. 不做的事

- 不改 ProceduralMemory（已是 0）。
- 不改 Stable Envelope / schemaVersion / public API / release gate。
- 不改 tickHash 算法。
- 不做 memory compaction。
- 不扩大到其他 memory 字段。
