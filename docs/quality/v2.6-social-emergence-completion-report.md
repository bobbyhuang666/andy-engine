## 关键技术发现与修复

### 1. FactProvider 默认 Evidence 伪造 Bug

**问题**：PUBLIC facts（如 EVENT 类型）在 KnowledgeStore 中无证据条目时，`_attachEvidence()` 伪造 `_evidence: { source: 'direct', confidence: 1.0 }`。

**影响**：told/informed 传播的事实被 checker 误判为有 direct 证据，使其他 agent 的 AGENT_STATE 表达（activity/emotion/needs）被错误正当化。

**修复**：无 KS 条目时不附加 `_evidence`。Fact 返回原样，无证据字段。

**回归测试**：`tests/unit/narrative/fact-provider-evidence.test.js` 新增 2 个 case。

### 2. D6 判定逻辑不可达（B1）

**问题**：`judgeDimension()` 中 D6 专用判定块位于通用路径之后。D6 的 `entry` 首个 token 是 `social-emergence.test.js`，当 social-emergence pass 时，通用路径直接返回 Pass，D6 的 3 文件判定逻辑永远不可达。

**影响**：gossip-propagation 或 emotion-contagion-cluster 失败时 D6 仍报 Pass。

**修复**：将 D6 判定块移至 D3 之后、通用路径之前。删除不可达代码。

**回归测试**：`tests/unit/aliveness-report-d6-judgment.test.js`（8 个 case）。

### 3. told EVENT 不正当化 AGENT_STATE

**确立规则**：told EVENT 只传递事实存在性，不传递 agent 的内部状态。

- told EVENT → 不正当化 activity（不能从"听说 Bob 开会"推断"Bob 正在开会"）
- told EVENT → 不正当化 emotion（不能从"听说 Bob 生气"推断"Bob 生气"）
- told EVENT → 不正当化 needs（不能从"听说 Bob 饿了"推断"Bob 饿了"）

只有 direct/observed/overheard 证据（且 narrator 不在场）可正当化 activity；narrator 物理在场可正当化 emotion/needs。
