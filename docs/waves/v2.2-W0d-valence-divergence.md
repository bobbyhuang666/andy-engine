## 1. 背景

W1 修复 _nextId + reflection counters 后，L4 分叉从 tick 50 推到 tick 67。tick 66 两边完全一致（behB/valence/joy/tsr/tsdc 全等），tick 67 joy 一致但 **valence 分叉**（full 0.083748256659 vs restored 0.083664265184，差 8e-5），导致 behB 分叉（3e-7）。

W0d 定位第四层根因：tick 67 valence 分叉的首个源头。高优先级候选是 `PersonalMemory.consolidate` 内部 RNG 消耗（`_logisticNoise` line 1001 用 `_rng.next()`），但**不假设**——先定位第一个 hidden-state 分叉或第一个 RNG draw 分叉。

## 4. 诊断方法

按总规划师要求，不假设 consolidate 是根因，按优先级定位：

1. **先证 tick 66 完全一致**：dump tick 66 全字段（含 hidden state：emotion 全维度、needs、behaviorField、memory accessCount/lastAccessed/presentations、_tickCache 等），确认无隐藏分叉。
2. **定位 tick 67 第一个分叉字段**：不限于 valence，逐字段 dump 找首个分叉（可能在 valence 之前的 hidden 字段）。
3. **RNG draw 序列对比**：instrument `RNG.next()`，记录 tick 67 full vs restored 的每次 draw（caller + value），找第一个不同 draw 及其函数。
4. **若 RNG 一致但 valence 仍分叉**：查浮点/ordering/Date/simTime。
5. **若未持久化字段**：列字段、所属对象、toJSON/fromJSON 当前行为、best-effort 方案。

## 5. W0d 必须回答的 8 个问题

1. tick 66 完全一致是否已由 dump 证实？（含 hidden state）
2. tick 67 的第一个分叉字段到底是 valence，还是 valence 之前的某个隐藏字段？
3. Leo 在 tick 67 前后是否触发 consolidate / recall / regulation / appraisal？
4. 两边 RNG draw 序列是否完全一致？若不一致，第一个不同 draw 在哪个函数？
5. `PersonalMemory.consolidate` 内部合并 pair / noise / similarity / importance 是否一致？
6. memory entry 的 accessCount / lastAccessed / presentations / activation / timestamp 是否完整持久化？
7. valence 更新由哪个函数触发，输入是否一致？
8. 这是 memory runtime state 缺口、emotion runtime state 缺口，还是 RNG 消耗路径缺口？
