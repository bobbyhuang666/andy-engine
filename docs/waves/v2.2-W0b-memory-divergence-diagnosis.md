## 4. 诊断方法

instrument `PersonalMemory.addExperience`（line 158）捕获每次调用：
- caller stack（谁调用 addExperience）
- event（content/type/id）
- tick（world.clock.tickCount）
- agentId
- source（哪个 runtime 路径触发）

跑 full（0-59）与 restored（0-49 序列化→恢复→50-59），逐条比对 memory creation timeline，定位：
1. restored 第一条额外 memory（full 没有的）
2. 它的 caller / event / 触发路径
3. full 为什么没生成同条（触发条件差异）
4. 触发条件依赖的状态是否持久化

## 5. W0b 必须回答的 7 个问题

1. tick 50-59 restored 额外 memory 的第一条是哪一条？（mem id + content + tick）
2. 它由哪个函数调用 `addExperience` 创建？（caller 路径）
3. full run 为什么没有创建同一条？（触发条件差异）
4. 触发条件依赖什么状态？
5. 该状态是否被 toJSON/fromJSON 持久化？
6. 这是新的 runtimeSnapshot 缺口，还是 `_nextId` 修复引入的副作用？
7. W1 是否仍只需修 EventDispatcher，还是需扩展到 memory/event-processing 状态？
